# NewsCatcher 使用教程与配置指南

本文档将详细指导您如何配置和使用 NewsCatcher 机器人系统。

系统设置页按 Material Design 3 分为五个 Tab：**抓取**、**AI**、**分类**、**通知**、**存储**。保存、测试与删除等反馈均使用页面底部 Snackbar 或确认 Dialog，不会弹出浏览器原生弹窗。

第三方前端请对接 `/api/v1`，使用 `Authorization: Bearer <API Key>`。密钥在 **存储** Tab 中查看或轮换，完整说明见 [api.md](./api.md)。

## 1. 获取 X (Twitter) Cookie 凭证

NewsCatcher 通过 X 账户登录会话抓取推文。后端使用现行 GraphQL `Viewer` 校验登录，并为请求自动生成 `x-client-transaction-id`。

### 获取步骤：
1. 使用 Chrome / Edge 浏览器打开 [https://x.com](https://x.com) 并登录您的 Twitter 账号。
2. 按 `F12` 或右键选择“检查”，打开**开发者工具 (Developer Tools)**。
3. 切换到 **Application (应用)** 选项卡（Safari / Firefox 为“存储”）。
4. 在左侧展开 **Cookies** -> 点击 `https://x.com`。
5. 复制凭证，任选一种方式：
   - **推荐**：复制该站点下的完整 Cookie 字符串（包含 `auth_token`、`ct0`，以及 `kdt` / `twid` 等），直接粘贴到设置页任一输入框。
   - 或只复制两个键的值：`auth_token` 与 `ct0`（CSRF Token）。
6. 打开 **系统设置 → 抓取**，填入后点击 **测试 Cookie 有效性**。

> **提示**：测试成功会通过 Snackbar / 结果文本显示当前账号用户名。完整 Cookie 比只填两个字段更不容易被 X 判定为不完整会话。

## 2. 配置 AI 模型 (OpenAI 兼容 API)

NewsCatcher 能够对接任何兼容 OpenAI API 格式的大语言模型。

### 配置步骤：
1. 进入 **系统设置 → AI**。
2. 填写以下信息：
   - **API Base URL**：例如 `https://api.openai.com/v1`、`https://api.deepseek.com` 或本地 Ollama 的 `http://localhost:11434/v1`
   - **API Key**：您的 LLM 服务提供商提供的 API 密钥
   - **Model 名称**：例如 `gpt-4o`、`gpt-3.5-turbo`、`deepseek-chat` 或 `qwen2.5`
3. 点击 **测试 AI 接口** 确认连线正常。
4. 点击底部的 **保存系统设置**。

## 3. 配置 AI 提示词预设

同一页 **系统设置 → AI** 下方可管理多套提示词，用于自定义模型人格与总结文风。抓取时只使用当前启用的一套。

- **切换当前预设**：在下拉框中选择，立即生效，无需再点总保存。
- **新建 / 编辑**：可分别填写预设名称、System 提示词（人格）与 User 提示词模板。
- **复制**：基于现有预设生成副本后再改。
- **恢复默认**：仅内置「专业主编」可用，会还原为系统默认文案。
- **删除**：不能删除内置预设，也不能删除当前正在使用的预设（请先切换到其他套）。

User 模板可用变量：

| 变量 | 含义 |
| --- | --- |
| `{{authorName}}` | 推文作者显示名 |
| `{{authorUsername}}` | 作者用户名 |
| `{{createdAt}}` | 推文时间 |
| `{{url}}` | 原推链接 |
| `{{text}}` | 推文正文 |
| `{{categoryHint}}` | 当前启用的分类提示 |
| `{{jsonSchema}}` | 系统要求的 JSON 输出契约 |

点击编辑对话框中的变量 Chip 可插入到 User 模板。若模板中未包含 `{{jsonSchema}}`，后端仍会自动追加 JSON 输出要求，避免解析失败。

必须由模型输出的字段：`isNews`、`title`、`summary`、`markdownContent`、`category`、`importance`。

## 4. 添加与管理 X 抓取源

进入左侧导航栏的 **抓取源管理**，您可以自由添加监控规则：

- **关键词搜索 (Search)**：如 `OpenAI min_faves:50`（包含 OpenAI 且点赞数大于 50 的推文）
- **指定推主账号 (User)**：如 `from:SamA`（抓取 Sam Altman 发布的推文）
- **Hashtag 话题 (Hashtag)**：如 `#AI` 或 `#Finance`

可以随时通过开关启用/禁用某个抓取源，或点击删除按钮移除源。删除前会弹出 M3 确认框。

## 5. 设置新闻分类与过滤规则

进入 **系统设置 → 分类**：

- **添加分类**：在输入框中输入新的分类名称（如 `加密货币`、`芯片`），点击“添加分类”。
- **删除分类**：点击分类标签右侧的关闭按钮，即可删除旧的或默认的分类。
- **勾选保留规则**：勾选框选中的分类表示**目标保留分类**。当 AI 在提炼推文后，只有被归类为已被勾选分类的新闻，才会保存到 SQLite 数据库中，未勾选的将被自动过滤丢弃。

## 6. 配置定时自动化抓取

在 **系统设置 → 抓取** 中的定时区域：

1. 开启 **启用定时自动抓取** 切换开关。
2. 设定时间间隔，如“每 `1` `小时` 自动抓取一次”或“每 `30` `分钟` 自动抓取一次”。
3. 保存设置后后台将按计划自动运行。
4. 亦可随时点击右上角的 **立即抓取新闻** 进行手动触发。
5. 在 **抓取日志** 页面可以查看每一次运行的抓取条数、入库新闻数与执行状态。

## 7. 配置 Telegram & QQ 机器人通知转发

在 **系统设置 → 通知** 中支持以下三种通知手段：

### Telegram Bot 通知
1. 在 Telegram 搜索 `@BotFather` 创建自己的 Bot 并获取 `Bot Token`。
2. 将 Bot 邀请至个人聊天或频道，获取对应 `Chat ID`。
3. 开启“启用 Telegram Bot 通知”，填入凭证后可点击 **发送测试 Telegram 消息** 验证。

### QQ 机器人通知 (QQ Open API v2)
严格遵循 [QQ 机器人 v2 开放平台规范](https://bot.q.qq.com/wiki/develop/api-v2/)。
1. 在 QQ 开放平台注册机器人并获取 `AppID` 和 `ClientSecret`。
2. 若用于频道，填入 `Channel ID`（子频道 ID）；若用于个人或群聊，填入对应的 `OpenID`。群聊 OpenID 会自动回退到 `/v2/groups/` 接口。
3. 开启“启用 QQ 机器人通知”，点击 **发送测试 QQ 消息**。

系统会按现行规范附带 `X-Union-Appid` 与主动消息所需的 `msg_seq`。

### 自定义 Webhook
支持 Discord、Server酱、Bark 等服务，开启后填入对应生成的 Webhook 完整 URL 即可。

## 8. 原文保留与图片本地存储设置

在 **系统设置 → 存储**：

- **保留推文原文**：开启后，生成的 Markdown 文档底部会自动附带推文正文原文引用。
- **自动下载图片到本地**：开启后，系统会自动将推文附带的配图下载保存到本地，并在阅读器中展示。
- **自定义存储路径**：默认图片保存在项目运行目录下的 `/media`。可指定任意绝对路径（如 `/data/images` 或 `D:\newscatcher\media`）。

## 9. 新闻浏览与 Markdown 阅读器

在 **新闻简报** 页面：

- **检索与过滤**：使用顶部搜索框可按标题、正文、作者模糊搜索；点击分类芯片可按分类筛选。
- **查看 Markdown 详情**：点击任意新闻卡片，即可弹出 M3 样式的阅读器，可在「新闻报告」与「推文原文」之间切换，并查看原推链接与本地/远程配图。
- **删除新闻**：阅读器内删除会先弹出确认 Dialog。
